## R6 — one commit path
- `WebhookContractFulfillmentHandler` commits `paid` through payment-base's `ContractCommitServiceInterface`
  (required). The private DomainException-swallowing ladder (`advanceToAuthorized`, `advanceToCommitted`) is gone.
  A refusal or a chain that leaves the contract open fails the delivery, so Mollie retries.
- Root cause of the first red CI: Mollie never tagged payment-base's `PaymentAuthorizedEventHandler` (priority 90)
  and `ContractCommitmentHandler` (priority 80). On a Mollie-only shop the chain was empty and `commit()` returned
  `pending`. It only worked on shops where Stripe or PayPal brought the tags. `services.yaml` now carries the same
  definitions as Stripe and PayPal (`aa54294`). Nothing else in Mollie raises these events.
- `WebhookEndToEndTest` names the contract state and the webhook action when it fails (`67ea35c`).

## W5 — shared webhook guards
- The guard chain is payment-base's `Webhook\Guard\*` (`mollie.webhook.guard_chain`: payload size → HTTPS →
  rate limit 120/60 s). The 8 module guard classes and their tests are removed.
- The rate limit keys on payment-base's `TrustedProxyClientIp` (settings "Webhooks"). Without the resolver the
  endpoint answers 503.
